### 文档在线预览（已完成）

- 目标：在知识库详情页点击文档即可在原文件层面在线预览，不依赖 RAGFlow Chat/Agent。
- 范围：支持已上传的 PDF、DOCX、MD、TXT；PDF 用浏览器原生 iframe，MD/TXT 展示原文，DOCX 使用前端 `docx-preview` 渲染；Web 新增依赖 `docx-preview@^0.4.1`。
- 后端：新增 `GET /api/documents/:id/content`，流式返回本地 `UPLOAD_DIR` 原文件；按会话 `tenantId`、知识库/文档软删除状态和 `AccessControlService.canRead` 复核，越权与跨租户统一 404；`tenant_admin` 角色覆盖，`knowledge_admin` / `security_admin` 的元数据可见性不等于内容读取权。

- Web BFF：透传 `Range` / `If-Range` 请求头，并回传 `Content-Length`、`Content-Range`、`Accept-Ranges`、`Content-Disposition`、`X-Content-Type-Options`。

- 组件复用：预览弹窗移至 `apps/web/components/document-preview-dialog.tsx`，只依赖 `documentId/title/sizeLabel`；知识库详情与聊天引用共用同一个组件和内容接口。

## 已确认决策（不要再改）

1. **登录**：使用现有 MySQL 数据库，邮箱 + 密码登录；不做 Keycloak / OIDC / SSO / IdP / SCIM。MVP 单租户。
2. **知识库默认 ACL**：动态计算。新增 `knowledge_base_acls` 表；有效权限 = 知识库默认 + 文档例外；deny 优先；不物化到文档 ACL。增加 `knowledge_bases.acl_version` 用于缓存失效。
3. **模型配置**：用户级。每个登录用户都可以配置自己的 OpenCode Go / DeepSeek；模型列表和默认模型按用户隔离；API Key 服务端加密存储，浏览器只拿脱敏信息。
4. **文档存储**：本地磁盘，`UPLOAD_DIR=D:\PiChat\uploads`，不接 MinIO/S3。Worker 读取本地文件后上传给 RAGFlow。
5. **成员与组**：来自本地 MySQL，不使用 IdP。成员页的“IdP 只读同步”文案必须改掉；MVP 先种子数据，后续再做本地成员/组编辑和密码重置。
6. **垂直切片**：登录 → 单知识库/文档 → 文档 ACL → 用户级模型配置 → `kb.search` → SSE 回答 + 引用。先完成这条链路，再扩展。
7. **ACL 写权限**：`tenant_admin` + `knowledge_admin`；`member` / `security_admin` 只读。
8. **Agent Runtime 通信**：API ↔ Runtime 只走内网 `/internal/*`，共用 `INTERNAL_SHARED_SECRET`；Runtime 工具通过业务 API `/internal/access/scope` / `check` 计算和复核 ACL，不直连业务库。
9. **会话持久化**：Runtime 持久化 Pi JSONL（模型上下文、工具轨迹、compaction），业务 API 持久化 MySQL `messages`（产品消息、引用、状态、usage）。两边由同一次 run 产生，API 不读 JSONL，Runtime 不写聊天消息表。
10. **assistant 落库**：Runtime 在 `run.end` 携带最终快照；业务 API 以此写 MySQL，并累积增量事件作为流中断兜底。用户消息在 run 启动成功后写入，失败重试不重复插入用户消息。
11. **kb_read 输入**：只接受 `kb_search` 返回的引用序号；Runtime 从本轮 citation registry 解析内部文档与 RAGFlow 文档 ID，不接受模型传入的 `documentId`。
12. **知识库创建**：MVP 同步创建 RAGFlow dataset，成功后才写 MySQL；失败返回 503，不写半成品；不引入 provisioning 状态。
13. **知识库删除**：软删除（`knowledge_bases.deleted_at`），不物理删除 MySQL 行；知识库名称在租户内仍保持唯一。
14. **清理失败**：DB 软删除优先；RAGFlow/Redis/本地清理失败不回滚，接口仍返回 204，审计记录 cleanup 结果并保留补偿线索。
15. **批量授权**：一次只支持同一知识库内多文档、整体替换 exceptions；不支持跨库或追加模式。

## 硬约束

- `apps/web` 只做 UI 和 BFF，不直连 RAGFlow；API Key 永远不进浏览器。

- ACL 缓存 key 必须带 `acl_version`；权限变更后下一次调用立即生效。
- 开源 RAGFlow 只有 dataset 级权限，不要依赖它的权限 UI。
- Pi 内置的 `read/write/edit/bash` 必须禁用，只注册知识库工具；Runtime `cwd` 用每会话隔离空目录。
- Runtime 只通过 `INTERNAL_SHARED_SECRET` 保护的 `/internal/*` 通信；`kb_read` 只接受引用序号，不接受模型传入 `documentId`。
- Pi JSONL 由 Runtime 写，MySQL `messages` 由业务 API 写；API 不读 JSONL，Runtime 不写聊天消息表。
- SSE 事件必须复用 `packages/shared/src/sse.ts`，不要另造格式。
- 模型配置 Key 必须服务端加密（`model_configs.encrypted_api_key`），只在单次 run 内存中出现，不得明文入库、写磁盘、写日志或进 SSE。
- 不要手改 `packages/db/drizzle/` 下已生成的 SQL；Schema 改动后运行 `pnpm db:generate`。
- 不要提前做 MCP、CLI、多租户 SaaS、HA、RAGFlow Chat/Agent。
