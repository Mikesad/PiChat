## 已确认决策（不要再改）

1. **登录**：使用现有 MySQL 数据库，邮箱 + 密码登录；不做 Keycloak / OIDC / SSO / IdP / SCIM。MVP 单租户。
2. **知识库默认 ACL**：动态计算。新增 `knowledge_base_acls` 表；有效权限 = 知识库默认 + 文档例外；deny 优先；不物化到文档 ACL。增加 `knowledge_bases.acl_version` 用于缓存失效。
3. **模型配置**：用户级。每个登录用户都可以配置自己的 OpenCode Go / DeepSeek；模型列表和默认模型按用户隔离；API Key 服务端加密存储，浏览器只拿脱敏信息。
4. **文档存储**：本地磁盘，`UPLOAD_DIR=D:\PiChat\uploads`，不接 MinIO/S3。Worker 读取本地文件后上传给 RAGFlow。
5. **成员与组**：来自本地 MySQL，不使用 IdP。成员页的 “IdP 只读同步” 文案必须改掉；MVP 先种子数据，后续再做本地成员/组编辑和密码重置。
6. **垂直切片**：登录 → 单知识库/文档 → 文档 ACL → 用户级模型配置 → `kb.search` → SSE 回答 + 引用。先完成这条链路，再扩展。

## 硬约束

- `apps/web` 只做 UI 和 BFF，不直连 RAGFlow；API Key 永远不进浏览器。

- ACL 是唯一事实源：检索前计算 `allowedDocumentIds` → RAGFlow 同时传 `dataset_ids` + `document_ids` → 检索后复核 → 引用展示前再复核。
- ACL 缓存 key 必须带 `acl_version`；权限变更后下一次调用立即生效。
- 开源 RAGFlow 只有 dataset 级权限，不要依赖它的权限 UI。
- Pi 内置的 `read/write/edit/bash` 必须禁用，只注册知识库工具；Runtime `cwd` 用隔离空目录。

## 第一冲刺（先做这些，不扩到全链路）

**目标：真实登录 + 动态 ACL + 种子数据 + 知识库/权限薄接口，并接上现有登录页和知识库/权限页。**

### 1. Schema 变更

- `users.password_hash`（scrypt；格式建议 `scrypt$saltHex$hashHex`）。
- `auth_sessions`：id、tenant_id、user_id、token_hash、expires_at、created_at、last_used_at。
- `knowledge_base_acls`：id、tenant_id、knowledge_base_id、subject_type(user/group)、subject_id、permission(read/deny)、created_at；唯一约束 `(knowledge_base_id, subject_type, subject_id)`。
- `knowledge_bases.acl_version`（int，默认 0）。
- `model_configs` 增加 `user_id`，唯一约束改为按用户隔离（本轮可先设计，接口下一冲刺做）。
- 生成迁移；执行 `db:push` 前必须得到用户同意。

### 2. 种子数据

- 参考 `apps/web/lib/admin-data.ts` 的 mock 数据：1 个租户、14 个用户、6 个组（含 `g-platform`）、4 个知识库、16 篇文档、默认访问与文档例外。
- 种子密码统一为 `123456`；数据库只存 hash。
- 至少保证张明（tenant_admin）与王芳（member/售后组）登录后看到的文档范围不同。
- 写入 `knowledge_base_acls` 和 `document_acls`，`acl_version=1`。
- seed 要可重复执行；不要删除非 demo 租户的数据。

### 3. 认证

- `POST /api/auth/login`：邮箱 + 密码；校验 scrypt；检查 `status=active`；创建 session token（32 字节随机），数据库存 sha256，HttpOnly Cookie `pichat_session`，`SameSite=Lax`，生产环境 `Secure`，7 天过期。
- `POST /api/auth/logout`：删除 session + 清 Cookie。
- `GET /api/auth/me`：返回当前用户（不含密码）。
- Session guard / `@CurrentUser()`；后续受保护接口统一从会话取 principal。
- 前端 BFF 路由：`apps/web/app/api/auth/{login,logout,me}/route.ts` 转发 cookie；`AuthProvider` 改为调用 `/api/auth/me`，移除 localStorage mock 会话。
- 登录页：去掉 SSO 和“任意密码”文案；增加种子账号提示；显示真实错误（邮箱不存在/密码错误/账号停用）。
- 单租户 MVP：按 email 查用户；如果未来多租户，再加企业域/租户码。

### 4. ACL 服务

- 在 API 内实现 `AccessControlService`，复用 `@pichat/access-control` 的纯策略。
- `listReadableDocumentIds(principal)`、`canRead(documentId, principal)`、有效访问人数、访问检查原因、用户组展开。
- 有效条目 = `knowledge_base_acls` + `document_acls`；deny 优先；`tenant_admin` 覆盖。
- 缓存 key 包含 `tenantId + knowledgeBaseId + aclVersion`；ACL/默认范围变更时递增 `acl_version`。
- 单测：默认生效、文档例外覆盖、deny 优先、tenant_admin 覆盖、跨租户拒绝。

### 5. 薄 API + 现有页面接真

- 先做只读/最小写接口：
  - `GET /api/knowledge-bases`（按当前用户权限过滤）
  - `GET /api/knowledge-bases/:id`
  - `GET /api/knowledge-bases/:id/documents`
  - `PUT /api/documents/:id/acl`（更新文档例外，递增 acl_version）
  - `POST /api/access-check`（可选，返回允许/拒绝原因）
- 把 `apps/web/app/(admin)/knowledge` 与 `permissions` 的 mock 数据源替换为这些接口。
- 先不做上传、RAGFlow、SSE、模型配置接口。
- ACL 变更写 `audit_logs`（至少记录 actor、action、resource、结果）。

### 6. 文案修正

- 登录页移除 OIDC/SSO/“任意邮箱”。
- 成员页从 “IdP 只读同步” 改为 “本地数据库成员，当前只读”。
- 模型配置抽屉里的 sessionStorage 文案标记为过渡方案，下一冲刺改为服务端加密。
